# 2026年7月21日以降の画像処理障害とアクセス減少

GA4プロパティ`489868388`のデータを、障害前29日（6月22日〜7月20日）、障害後の初期29日（7月22日〜8月19日）、直近18日（8月20日〜9月6日）で比較した。7月21日は切り替わり日として期間比較から除外した。

## 結論

画像処理が7月21日に動かなくなったという説明は、GA4の時系列と強く一致する。

当時は処理開始・成功イベントを実装していなかったため、障害を直接証明するログはない。ただし、処理結果が表示された利用者に発火する`pro_high_precision_impression`は、7月20日まで1日85〜161件発生していた。7月21日は56件に急減し、7月22日以降は0件になった。

同時期の来訪自体は、7月21日176ユーザー、7月22日171ユーザー、7月23日163ユーザーと続いていた。このため、先にアクセスがなくなって結果イベントが消えたとは考えにくく、来訪者が結果へ到達できなくなった時系列と整合する。

平均セッション継続時間は517秒から218秒、直近131秒へ低下した。セッション数÷ユーザー数も1.95から1.40、直近1.36へ低下した。機能停止後に利用の深さと再利用が失われ、その後は検索流入も継続して減った可能性が高い。

Pro購入クリックのユーザー比率は障害前4.9%、障害後初期5.6%、直近4.8%で大きく崩れていない。Pro契約機会が減った主因は、購入意向率の急落より、処理結果へ到達する利用者と流入母数の減少と考えられる。

## 解釈上の制約

- `pro_high_precision_impression`は処理成功専用イベントではなく、当時の結果画面表示の近似指標として扱う。
- 旧イベントの`source`パラメータがGA4の流入元と衝突していたため、詳細な参照元名は信頼できない。ここでは主に標準チャネルグループを使った。
- GA4だけでは、検索順位低下が障害の結果か、別の検索要因かを断定できない。検索表示回数、順位、クリック率の切り分けにはGoogle Search Consoleが必要。

## 復旧後の判定

公開後は新設したイベントで次を7日・14日・30日ごとに確認する。

1. 処理完了率：`image_processing_completed` ÷ `image_processing_started`
2. 正常完了率：`result_status = success`の完了数 ÷ 開始数
3. 保存到達率：`image_download_completed` ÷ `image_processing_completed`
4. 再利用：セッション数÷ユーザー数とリピーター数
5. 集客回復：Organic Searchのユーザー・セッションの日平均
6. Proファネル：処理完了者から`pro_purchase_click`、`checkout_started`、`checkout_completed`への到達率

処理完了率が回復してもOrganic Searchが戻らない場合は、機能障害の解消と集客回復を分けて扱い、Search Consoleのクエリ・ページ別データから回復施策を決める。
