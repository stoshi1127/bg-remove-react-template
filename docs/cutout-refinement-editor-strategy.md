# 仕上げ修正エディタ 方針・進行状況

最終更新: 2026-09-18
現在の状態: **Phase 2再設計 / 一括仕上げ修正ページの実装前**
実装状況: **現行の単画像`/refine/access`方式はPreview検証で複数画像が失われる問題を確認したため、本番採用せず、一括編集workspace方式へ改修する**

次期実装の確定計画は[`batch-refinement-editor-plan.md`](./batch-refinement-editor-plan.md)を参照する。

## 1. この文書の目的

背景透過後の画像を部分的に修正できる「仕上げ修正エディタ」について、プロダクト方針、MVPの範囲、技術上の前提、Pro提供方法、検証指標、実装状況を一か所で管理する。

作業を進めるたびに、この文書の「進行状況」とチェックリストを更新する。コードが存在するだけでは完了扱いにせず、テストと計測確認まで終わった段階で各Phaseを完了とする。

## 2. 決定した方針

- アンケート結果を待たず、仕上げ修正エディタのMVP実装へ進む。
- 最初はAI処理ではなく、ブラウザ内で動作する手動の「消去ブラシ」「復元ブラシ」を実装する。
- 背景透過の結果を部分的に直せない現状を解消し、画像を完成させられることを最優先にする。
- AI消しゴム、自動輪郭補正、不要物の生成塗りつぶしは、手動エディタの利用状況を確認してから追加する。
- アンケートによる希望ではなく、エディタの起動、ブラシ使用、修正適用、保存、Pro導線到達という実利用で需要を検証する。
- 既存の背景透過、背景合成、ダウンロードの流れを壊さず、結果画像ごとの追加操作として導入する。

## 3. 現在提供している関連機能

### Free・ゲスト

- 標準の背景透過
- 最大30枚の一括処理
- JPG、PNG、WebP、HEIC/HEIFの読み込み
- 背景なし、単色、既存背景テンプレート
- `1:1`、`16:9`、`4:3`、元画像、被写体フィット
- 個別保存、ZIP一括保存
- 4MBを超える画像の自動圧縮
- 別ページのイージートリミング、イージートーン

### Pro

- 高精度背景透過
- 最大25MBを目安とする元画像処理
- 任意の背景画像アップロード
- AI背景生成
- ナチュラルブレンド
- 1K、2K、4K高画質化と一括高画質化
- プレミアムAI月30回
- 広告非表示

### 現在不足している機能

- 背景の消し残しだけを部分的に消す操作
- 誤って消えた髪、服、商品などを部分的に戻す操作
- ブラシで修正した透過状態を、選択済みの背景へ再合成する操作
- 修正の取り消し・やり直し
- AI消しゴム（公開画面では「準備中」）

## 4. なぜ先に実装するのか

- 背景透過サービスの中心作業そのものを完成させる機能で、特定用途に限定されない。
- 個人SNS、仕事資料、EC、デザインのいずれでも、輪郭や消し残しの修正は発生し得る。
- 現在の「標準」または「高精度で全体を再処理」だけでは、一部分だけを直せない。
- 手動編集基盤は、将来のAI消しゴムや自動輪郭補正にも再利用できる。
- ブラウザ内Canvasで実装できれば、手動修正自体の追加AI原価を抑えられる。

## 5. MVPの対象範囲

### 必須

- 結果画像ごとの「切り抜きを修正」ボタン
- 消去ブラシ：被写体として残っている不要部分のアルファ値を下げる
- 復元ブラシ：処理に使用した元画像から画素を戻し、アルファ値を上げる
- ブラシサイズ変更
- ズーム、パン
- 元に戻す、やり直す
- 修正前後の比較
- 適用、キャンセル
- 修正した透過画像を、現在選択中の背景・比率へ再合成
- 修正後の個別保存とZIP保存
- マウス、タッチ、ペンをPointer Eventsで扱う
- キーボード操作、フォーカス管理、ボタン名などの基本的なアクセシビリティ

### MVPで対応する処理

- 標準背景透過
- Pro高精度背景透過
- 背景なし
- 単色背景
- 既存テンプレート背景
- Proの任意背景画像（通常合成のみ）

### MVPでは対応しない処理

- AI背景生成後の完成画像
- ナチュラルブレンド後の完成画像
- AIによる不要物削除・生成塗りつぶし
- 自動輪郭検出・自動エッジ補正
- レイヤー編集
- テキスト、図形、フィルター編集
- 複数画像を同時に同じブラシ操作で編集
- 編集プロジェクトのサーバー保存

AI背景生成とナチュラルブレンドは、背景と被写体が統合された完成画像を返す。通常の透過マスク編集とはデータ構造が異なるため、MVPでは「切り抜きを修正」を表示しないか、非対応理由を明示する。

## 6. 決定した提供条件

### ゲスト・無料アカウント

無料アカウントは存在するが、現時点では新規登録導線を提供していない。そのため、ゲストと無料アカウントを同一条件として扱う。

- 最初の1画像は、広告なしで仕上げ修正を利用できる。
- 初回分でも、透過・復元・ブラシサイズ・移動・ズーム・Undo/Redo・比較・適用・保存をすべて利用できる。基本操作を部分的にPro限定にはしない。
- 初回無料を消費した後は、AdSense Offerwallを設定した判定ページを経由する。
- AdSense管理画面で`1ページビュー`を選択できることを確認済み。広告視聴後の利用資格は1ページビューとする。
- アプリ側では判定ページへ持ち込んだ画像に紐づく1回限りの編集権として扱う。
- 広告在庫がなくOfferwallが表示されない場合は、原価の低い手動編集に限り無料で通過できるフォールバックとする。
- 高精度処理、AI背景、AI消しゴムなどサーバー原価のある機能は、このアクセス権では解放しない。

### Pro

- 手動の仕上げ修正を広告なし・枚数制限なしで利用できる。
- 高精度背景透過結果の修正、高画質保存など、既存のPro条件は維持する。
- 将来のAIスマートブラシ、AI消しゴム、自動輪郭補正は手動編集とは分離し、プレミアムAI回数または別のPro条件で提供する。

### 初回無料枠と画像単位のアクセス権

- エディタを開いただけ、またはキャンセルしただけでは初回無料枠を消費しない。
- 初回無料枠は、最初に修正を適用できた時点で消費する。
- 2回目以降に「切り抜きを修正」を押した時点で、編集画像をブラウザ内へ一時保存して判定ページへ移動する。
- 判定ページでOfferwallが閉じた後、利用者が「この画像を仕上げ修正する」を押した時点で、対象画像に紐づく一時アクセス権を発行する。
- アクセス権は`sessionStorage`へ画像ID単位で保存し、別画像には流用しない。
- 編集後の保存段階で突然OfferwallやPro購入を要求しない。条件はエディタを開く前に提示する。

### MVPでの状態管理

- ゲストと無料アカウントの初回無料利用済み状態は、ブラウザの`localStorage`へ保存する。
- 判定ページへ移動する際の元画像、透過画像、画像名、編集再開情報は、容量制限の小さい`localStorage`ではなくIndexedDBへ一時保存する。
- 画像単位の一時アクセス権は`sessionStorage`へ保存し、編集画像はIndexedDBへ最大1時間保存する。
- ブラウザデータ削除、開発者ツール、直接URL操作による回避は完全には防止しない。手動編集はブラウザ内処理で追加AI原価がないため、強い不正防止より導入速度を優先する。
- 高精度処理、AI背景、AI消しゴムなど原価のある機能は、リワード利用権の対象に含めない。

### AdSense Offerwallを採用する理由と制約

- 現在のA8系スポンサー枠はリワード広告ではないため、利用権の付与には使用しない。
- Ad Exchangeを簡単に利用できる状況ではないため、Google Ad ManagerのGPTリワード広告を本番方式には採用しない。
- AdSense Offerwallは、広告視聴後に時間またはページビュー単位のサイトアクセス権を与える仕組みであり、画像ID単位の報酬付与イベントはアプリへ公開されない。
- 判定ページのHTMLとJavaScriptはOfferwall表示前から読み込まれるため、HTTPステータス、`fetch`、iframe、ページ内スクリプトだけで視聴完了を厳密に証明することはできない。
- 自動リダイレクトはOfferwallの背後でも動く可能性があるため使用しない。Offerwallが閉じた後に見える「仕上げ修正を開始」ボタンを利用者が押して遷移する。
- 広告表示前に、広告視聴でこの画像1枚を仕上げ修正できることを明示する。
- 本方式はソフトゲートとして手動編集だけに使用し、API原価のある機能の認可には使用しない。

### 判定ページの基本導線

初回無料枠を使い切った利用者に、エディタを開く前に次の流れを提示する。

1. 結果画面で「広告を見て仕上げ修正」または「Proで広告なし・無制限に修正」を選ぶ。
2. 広告を選んだ場合は対象画像をIndexedDBへ一時保存する。
3. `/refine/access`へ移動し、このURLだけをAdSense Offerwallの対象にする。
4. Offerwallが表示された場合は、利用者が広告を完了して閉じる。
5. 判定ページの「仕上げ修正を開始」を押す。
6. 画像単位の一時アクセス権を保存し、元の編集フローへ戻って対象画像を復元する。

Offerwallの広告在庫がない場合は判定ページがそのまま表示されるため、「仕上げ修正を開始」から無料で通過できる。これは障害ではなく、原価の低い手動編集に対する意図したフォールバックとして扱う。

### Proの扱い

- Proは判定ページを経由せず、結果画面から直接エディタを開く。
- AdSenseのPrivacy & Messaging APIでOfferwallを抑止できる場合は、既存の`isPro`判定と連携する。
- 抑止処理が失敗しても、Pro導線から判定ページへ移動しない構造を第一の防御とする。

## 7. 現行実装から見た技術上の前提

現在の通常処理は、おおむね次の順序になっている。

1. 元画像をHEIC変換またはFree向け圧縮する。
2. `/api/remove-bg`から透過画像を取得する。
3. 透過画像から被写体のバウンディングボックスを計算する。
4. 必要に応じて比率変更・背景合成を行う。
5. 合成後の`finalUrl`を`InFile.outputUrl`として保持する。

現状は背景合成前の透過画像URLを恒常的に保持していない。復元ブラシには、透過画像と同じ座標・寸法の元画像が必要になる。

### 想定するデータ追加

名称は詳細設計時に確定する。

- `processedSourceUrl`：実際に背景除去へ渡した元画像。HEIC変換・Free圧縮後の状態を保持する。
- `transparentOutputUrl`：背景合成前の透過画像。
- `refinedTransparentOutputUrl`：ブラシ修正後の透過画像。
- `hasRefinement`：修正適用済みかどうか。

### 想定する処理フロー

1. 背景除去へ渡す画像を、復元用ソースとして保持する。
2. `/api/remove-bg`の透過結果を`transparentOutputUrl`として保持する。
3. 通常どおり背景・比率を適用して`outputUrl`を作る。
4. エディタは`processedSourceUrl`と`transparentOutputUrl`を同じCanvas座標で重ねる。
5. 消去ブラシはマスクを透明へ、復元ブラシは元画像を不透明へ変更する。
6. 適用時に透過PNGを生成し、選択中の背景・比率を再適用する。
7. `outputUrl`、バウンディングボックス、保存対象URLを更新する。

### 詳細設計で確認する項目

- Free圧縮後の画像と透過結果の寸法が常に一致するか
- `fit-subject`を再計算するタイミング
- 修正後のバウンディングボックス再計算
- Undo/Redoを画像スナップショットで持つか、マスク差分で持つか
- 高解像度画像に対するCanvasメモリ上限
- Blob URL、Data URL、Vercel Blob URLのCORSとCanvas汚染対策
- 画面を閉じたときのObject URL解放
- 修正後に高画質化した場合のURL更新順序

## 8. UI方針

### 結果画面

- 各結果画像の「保存」「イージートリミングで編集」と同じ操作領域へ「切り抜きを修正」を追加する。
- AI背景生成・ナチュラルブレンド結果では、MVP中はボタンを非表示にする。
- 無料体験を導入する場合は、ボタン付近に「1枚無料で試せます」を事前表示する。

### エディタ

- PCでは中央に大きなCanvas、周囲にツールを配置する。
- スマートフォンではCanvasを優先し、主要ツールを画面下部へ固定する。
- 背景は市松模様を基本とし、白・黒背景への切り替えも検討する。
- 消去と復元を色だけで区別せず、アイコンと文字を併用する。
- 適用前に修正結果を確認できる状態を保つ。

## 9. 計測方針

画像、ファイル名、ブラシ座標、マスクデータはGA4へ送信しない。

候補イベント:

| イベント | タイミング |
| --- | --- |
| `refinement_editor_view` | エディタを開いた |
| `refinement_editor_started` | 最初のブラシ操作を行った |
| `refinement_editor_applied` | 修正を適用した |
| `refinement_editor_canceled` | 修正を適用せず閉じた |
| `refinement_export_completed` | 修正後画像を保存した |
| `refinement_trial_used` | Free体験を消費した |
| `refinement_pro_click` | エディタ関連のPro導線を押した |
| `refinement_reward_offer_view` | 初回無料後に判定ページ経由を開始した |
| `refinement_draft_saved` | 判定ページへ移動する画像を一時保存した |
| `refinement_access_page_view` | `/refine/access`を表示した |
| `refinement_access_continue` | 判定ページの「この画像を仕上げ修正する」を押した |
| `refinement_draft_restored` | IndexedDBから編集対象を復元した |

候補パラメータ:

- `user_plan`：`guest` / `free` / `pro`
- `processing_mode`：`standard` / `pro_high_precision`
- `tool_used`：`erase` / `restore` / `both`
- `placement`：`result_card` / `editor` / `export`
- `is_trial`：無料体験か
- `access_type`：`trial` / `offerwall_route` / `timed_access` / `pro`

1ストロークごとのイベントは送らない。編集セッション単位で一度だけ集計する。

### 確認する指標

- 処理完了ユーザーに対するエディタ起動率
- エディタ起動からブラシ使用までの到達率
- ブラシ使用から修正適用までの完了率
- 修正適用後の保存率
- Free体験利用者のPro導線クリック率
- Free体験利用者の決済開始・購入完了率
- 消去、復元、両方の利用構成
- 再訪時のエディタ再利用率

## 10. テスト方針

### 機能

- 消去ブラシで透明になる
- 復元ブラシで元画像の画素が戻る
- 細いブラシ、大きいブラシが正しく動く
- Undo/Redoの順序が崩れない
- 適用、キャンセル、再編集が正しく動く
- 修正後の背景なし、単色、テンプレート、任意背景の再合成
- `1:1`、`16:9`、`4:3`、元画像、被写体フィットの再出力
- 個別保存、ZIP保存、高画質化との連携

### 入力

- JPG、PNG、WebP、HEIC/HEIF
- Free圧縮された画像
- 透明部分を含む入力画像
- 縦長、横長、正方形
- 大きい画像、複数画像

### 操作環境

- マウス
- タッチ
- ペン入力
- キーボードのみ
- モバイル縦画面
- PCの狭い画面と広い画面

### 非機能

- 大画像でブラウザがメモリ不足にならない
- Canvas汚染やCORSエラーが発生しない
- エディタを閉じた後にObject URLを解放する
- 編集中に画像を外部へ追加送信しない
- 既存の背景透過、AI背景、高画質化、ダウンロードを壊さない

## 13. 現在の実装上の暫定仕様

- Google Ad Manager用の連携とPreviewシミュレーションは撤去済み。
- AdSense Offerwall判定ページ、IndexedDB引き継ぎ、画像単位アクセス権を実装済み。
- 実Offerwallの対象URL設定とPreview確認が終わるまでは、本番環境の提供条件を変更しない。
- 通常の標準透過とPro高精度透過だけを対象とする。
- AI背景生成・ナチュラルブレンド結果には修正ボタンを表示しない。
- 編集表示用Canvasは長辺最大1400pxへ縮小するが、ストロークは正規化座標で保持し、適用時に元の透過画像サイズへ再生する。
- 適用時のブラウザ負荷を抑えるため、4000万画素を超える画像は現時点では修正を確定できない。
- 修正履歴はエディタを閉じるまでのセッション内だけで保持する。
