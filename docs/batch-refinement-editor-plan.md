# 一括仕上げ修正ページ 改修計画

最終更新: 2026-09-18
状態: **実装完了・Preview外部検証待ち**

## 実装結果（2026-09-18）

- IndexedDB v2へ`workspaces`、`items`、`assets`を追加し、全件を単一トランザクションで保存する。
- `/refine/editor/trial`、`/refine/editor/rewarded`、`/refine/editor/pro`を実装した。
- 画像切替、下書き復元、初回1画像無料、残りロック、rewarded解放、Pro認可を実装した。
- 現在画像、選択画像ZIP、修正済み画像ZIPの保存を実装した。
- 容量事前判定、容量不足時の画像選択、IndexedDB失敗時の単画像フォールバックを実装した。
- 旧`/refine/access`と単画像draft保存を撤去した。
- 自動テスト45件と本番ビルドが成功した。実Offerwall、30枚、HEIC、実機モバイルはPreviewでの確認待ち。

## 1. 目的

透過処理後の全画像を一つの編集workspaceへ移し、画像の切替、透過・復元修正、個別保存、ZIP一括保存までを専用編集ページで完結させる。

現在の`/refine/access`往復では、元画面のReactメモリにある複数画像が失われ、選択した1枚だけが復元される。この構造を廃止し、編集ページ自体をAdSense Offerwallの対象にする。

## 2. 確定した提供条件

### ゲスト・無料アカウント

- 編集可能な透過画像は通常すべてworkspaceへ移す。
- 利用者が最初に修正を適用した任意の1画像は広告なしで利用できる。
- エディタの表示、ブラシ操作、キャンセルだけでは初回無料枠を消費しない。
- 最初の1画像を適用した後、残りの画像は一時的にロックする。
- Offerwall対象ページへ移動した後は、同じworkspace内の残り全画像を編集可能にする。
- 同じworkspace内の修正済み画像を再編集する際は広告を要求しない。
- 新しい処理バッチでは再度Offerwall判定を行う。
- 広告在庫なし、Offerwall非表示、IndexedDB利用不可、容量不足などの場合は、追加原価のない手動編集を無料で利用できるフォールバックを用意する。

### Pro

- Offerwallなしで最初から全画像を編集できる。
- 高精度透過結果と既存の高画質保存条件を維持する。
- Pro以外がPro用編集URLへ直接アクセスした場合は編集を開始しない。

### Offerwall

- `/refine/access`は廃止する。
- AdSenseのページ包含は`/refine/editor/rewarded`だけに設定する。
- 利用資格は`1ページビュー`に設定する。
- 広告視聴完了イベントはアプリから取得できないため、手動編集だけに使用するソフトゲートとする。
- 「広告1回で必ず1枚」とは表示せず、「短い広告を見ると、このバッチの残りを仕上げ修正できます」と説明する。
- 広告を拒否しても、既存結果の保存や新しい画像処理を妨げない。

## 3. 利用フロー

```text
画像をアップロード
    ↓
背景透過処理
    ↓
結果一覧
    ├─ このまま保存
    │    ├─ 個別保存
    │    └─ ZIP一括保存
    │
    └─ まとめて仕上げ修正（対象N枚）
         ↓
       workspace保存
         ↓
       初回無料 → /refine/editor/trial
       利用済み → /refine/editor/rewarded
       Pro      → /refine/editor/pro
         ↓
       画像を切り替えて編集
         ↓
       個別保存またはZIP一括保存
         ↓
       新しい画像を処理
```

編集ページを最終作業場所とし、元の結果一覧を復元して戻る導線は設けない。

## 4. 編集対象

### 対象

- 標準背景透過
- Pro高精度背景透過
- 背景なし
- 単色背景
- 既存テンプレート背景
- 通常合成のカスタム背景

### 対象外

- AI背景生成
- ナチュラルブレンド
- 処理エラー画像
- 処理元画像または透過画像を保持していない結果

対象外が含まれる場合は、遷移前に「全N枚中M枚を編集できます」と理由を表示する。

## 5. Workspace保存設計

IndexedDBはworkspace単位とし、`workspaces`、`items`、`assets`へ分離する。

### Workspace

- ID、スキーマバージョン
- `writing` / `ready` / `editing` / `completed`
- `trial` / `rewarded` / `pro`
- 無料対象画像ID
- バッチ解放状態
- 作成日時、最終操作日時
- 画像順序

### Item

- 画像ID、画像名、表示順
- 編集可否と対象外理由
- 処理モード
- 処理元asset参照
- 透過画像参照
- 修正後透過画像参照
- 背景、比率、バウンディングボックス
- 未修正、編集中、修正済み、編集対象外
- ブラシストローク下書き

### Asset

- workspace ID
- asset ID、用途、MIME type、サイズ
- Blob本体

再取得できるHTTPS画像はURLだけを保存する。Blob保存は、ページ移動で失われる処理元画像、非HTTPの透過画像、修正後透過画像、共通カスタム背景だけに限定する。完成画像、ZIP、Canvas表示用コピーは保存しない。

同じカスタム背景、高画質・標準画質が同一の画像、同一Blobを重複保存しない。

## 6. 容量・失敗時の扱い

- 保存前に対象Blobの合計サイズを算出する。
- `navigator.storage.estimate()`で空き容量を確認し、安全余裕を残せない場合は全件保存を開始しない。
- 通常は全画像を対象にし、容量不足時だけ画像選択画面を表示する。
- 非選択画像もメタデータと再取得可能な透過URLをworkspaceへ残し、編集不可・ダウンロードのみとする。
- 1画像も安全に保存できない、IndexedDBが無効、または書き込みに失敗した場合はページ移動せず、結果画面内の単画像エディタを無料フォールバックとして開く。
- workspaceは最初に`writing`として作り、全トランザクション完了後だけ`ready`へ変更する。
- 失敗時は部分保存されたworkspaceとassetsを削除する。
- 最終操作から1時間で期限切れとし、操作中は時刻を更新する。
- アプリ起動時、新規保存前、「新しい画像を処理」実行時に期限切れworkspaceを一括削除する。

## 7. 編集ページUI

### PC

- 左側: サムネイル一覧と修正状態
- 中央: 編集Canvas
- 下部: 透過、復元、移動、ブラシサイズ、Undo/Redo、比較
- 右上: 現在画像の保存、ZIP保存

### スマートフォン

- 上部: 画像名と`現在 / 総数`
- 中央: 編集Canvas
- 下部: 編集ツール
- 最下部: 横スクロールのサムネイル一覧
- 「適用して次へ」を主要操作にする

画像には「未修正」「編集中」「修正済み」「編集対象外」を表示する。未適用ストロークがある状態で移動する場合は、「適用して移動」「破棄して移動」「戻る」を表示し、自動適用はしない。

最初の1画像を適用後、残り画像にはロックとOfferwall導線を表示する。`rewarded`ページへ移動後は同じworkspaceを読み直して全画像を解放する。

## 8. 保存処理

- 現在画像の保存
- 選択画像の保存
- 全画像のZIP保存
- 修正済み画像だけのZIP保存

完成画像は、保存済みの透過画像、背景、比率、bboxから必要時に再構成する。既存の背景・比率合成処理をUIから独立した共通関数へ移し、結果画面と編集ページで共用する。

ZIP生成は1画像ずつ順番に再構成・追加し、複数のフルサイズCanvasを同時に保持しない。

## 9. コンポーネント・型の変更

- `CutoutRefinementEditor`からCanvas編集本体を分離し、モーダル表示とページ表示の双方で利用できるようにする。
- ブラシストローク型を公開し、`initialStrokes`と`onDraftChange`を追加する。
- バッチ編集コンテナが現在画像、画像切替、下書き、ロック、適用、保存を管理する。
- `RefinementWorkspace`、`RefinementWorkspaceItem`、`RefinementAssetRef`を追加する。
- 背景・比率合成処理を共通ユーティリティへ移す。

## 11. テスト・受け入れ条件

- IndexedDBの容量判定、重複排除、完了待ち、部分失敗ロールバック、期限切れ削除が動作する。
- 3画像以上で編集ページへ移動しても、全画像が一覧に残る。
- 再読み込み後もworkspaceと各画像の修正状態を復元できる。
- 初回適用前は無料枠が消費されず、適用後に残り画像がロックされる。
- `rewarded`ページ移動後、同じworkspaceの残り画像が解放される。
- ProはOfferwallなしで全画像を編集できる。
- 容量不足時に画像選択へ切り替わり、保存不能時に結果一覧を失わない。
- 単色、テンプレート、カスタム背景、元比率、被写体フィットの再合成結果が既存処理と一致する。
- 個別保存、全件ZIP、修正済みのみZIPが成功する。
- 30枚、HEIC、Free圧縮、Pro大画像、PC、スマートフォンを確認する。
- `/refine/editor/rewarded?fc=alwaysshow&fctype=monetization`で実Offerwallを確認する。
- 既存自動テスト、本番ビルド、既存ダウンロードの回帰確認を通す。

## 12. 実装順序

1. workspace型、IndexedDB v2、容量確認、期限切れ削除を実装する。
2. 背景・比率合成を共通ユーティリティへ分離する。
3. Canvas編集本体をページ表示へ対応させる。
4. バッチ編集ページと画像切替UIを実装する。
5. 初回1画像無料、残りロック、rewarded解放、Pro直接解放を接続する。
6. 個別・選択・ZIP保存を編集ページへ実装する。
7. 結果画面へ「まとめて仕上げ修正」を追加し、容量不足時の対象選択と無料フォールバックを実装する。
8. `/refine/access`と旧単画像Offerwall導線を撤去する。
9. GA4イベント、README、方針書を更新する。
10. Previewで広告なし、容量不足、再読み込み、実Offerwallの順に検証する。
